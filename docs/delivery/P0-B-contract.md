# P0-B 画面・同意・無効化/削除の契約

2026-09-13。P0-Aは通常34691452980・生成34694032847で検証済み。P0-Bはd1adb8eで通常34702137986・生成34700435807を確認し、必要な修正を統合した。0.7.0候補の一括実機も確認済み。以下は採用した契約を保持する。
P0-Bでは契約に依存しない型/保存操作から進め、P0-Aの検証完了を先取りしない。

## 利用者操作の意味

- 無効化: 新しい起動/イベント受付を止め、所有Runtimeの終了を待ち、通知/検索等の所有登録を解除する。保存データは保持する。
- 再有効化: 通常入口から再開できる。単に状態を切り替えただけでOS権限要求や業務操作を勝手に実行しない。
- 削除: 上記の停止/解除に加えて、Featureが宣言した所有データだけを削除し登録解除状態にする。コードをIPAから除去する操作とは区別する。
- 削除は対象/削除データの説明と明示確認を必須にし、取消時は何も変更しない。
- 停止/解除/削除に失敗した場合は完了とせず、どこまで進んだかと再試行を表示する。他ownerは継続。
- 処理が止まらない場合は終了診断を示す。timeoutを理由にデータ削除へ進まない。
- 削除後の再登録は初期状態とし、Feature同意を暗黙に復活させない。

## 共有契約と担当

親: Feature管理調停、Definition/Registry/hostの受付、アプリ内管理/同意UI、画面保持/提示/UIKit境界、共有CI/manifest/台帳。
保存担当: MiniAppRemovalProvider、Counter/Reminderの所有データ削除とtests。型の契約はid: MiniAppID、dataDescription: String、removeData: @Sendable () async throws -> Void。非同期削除callbackは既にowner予約・停止済みの層から呼び、同じ予約を再取得しない。Coreの他共有型には変更を広げない。
診断担当: MiniAppPermissionDeclarationとMiniAppConsentStore、専用tests/guide。同意はFeature/permission ID別の未確認・許可・拒否。権限タイトル/目的/拒否時動作を宣言する。UserDefaultsを明示注入し、他ownerを変更しない読み書き/削除と再起動保持を提供。OS権限そのものは変更しない。

削除providerはデータの削除のみを担当する。通知/category/検索等の登録解除とRuntime停止・設定の永続化は親の共通調停で行う。
OS同意とFeature内の利用同意は別。説明や名前空間を同一process内の強制セキュリティ隔離と表現しない。
readonly等で所有データがないFeatureはその旨を明示できる。provider不明を推測してディレクトリ全削除へ置き換えない。
既存のFeature APIと識別子/バックアップ互換性を維持する。

## 検証と提出

担当は独立branch/worktreeで一式を実装・自己確認して一度提出する。個別CIを起動しない。
親はCore契約と通常UIを統合してから一括レビュー・P0-B境界のCIを実行する。
取消/拒否、片側削除後の他方保持、再有効化/再登録、失敗途中の状態と再試行、提示中の外部遷移とUIKit終了を含める。
現在は型・接続を実装中であり、Feature無効化/削除を提供済みとは記載しない。
