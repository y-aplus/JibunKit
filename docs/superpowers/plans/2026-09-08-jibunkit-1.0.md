# JibunKit 1.0 完成計画

更新日: 2026-09-12。0.6.0公開済み、1.0未達。ユーザー指示により実装は停止中であり、
以下は再開後の判断に使う計画。この文書や旧CI通知だけで自律開発を再開しない。
[公開版とmainの状態](../../status.md)、[停止時引継ぎ](../../verification/2026-09-12-development-checkpoint.md)を先に確認する。

## 1.0.0の上位完成基準

> JibunKitへ統合した結果、独立アプリならOSやアプリ境界によって得られていた隔離・調停・所有権管理が失われるなら、その差分をJibunKitが可能な範囲で補う。

「可能」は技術的可能性で判断する。複雑・未要求・サンプル不在による先送りは未達として残す。各領域で独立時の保証、統合で失う差分、補完実装、競合/取消/終了/復帰の検証、補えない部分の根拠を記録する。既存のV1〜V6の成功だけでは1.0に到達しない。

## 完成を判断する条件

| ID | 条件 | 必要な証拠 |
| --- | --- | --- |
| V0 | 統合で失われる隔離・調停・所有権管理を技術的に可能な範囲で補完する | 差分台帳、補完実装と複数Featureの非干渉検証、残存制約の根拠。未対応・未調査を合格にしない |
| V1 | 独立Swift/SwiftUI Featureを、単独版とJibunKit版で同じ実装から開発・実行できる | 雛形、接続手順、単独起動・ホスト共存のCI。既存コードの分離手順と責任境界 |
| V2 | 複数画面・構造化データ・添付ファイルを持つ実用規模のFeatureで基盤の制限を検証する | 編集・再起動・検索または詳細遷移・他Featureとの独立保存。単純なText雛形だけを証拠にしない |
| V3 | データを保って更新・復旧できる | Featureごとのバックアップ、schema移行、破損拒否、選択外の維持、添付ファイルを含む復旧、失敗状態の説明 |
| V4 | システム連携をFeatureへ接続できる | Widget、App Intents、複数通知、URLの接続手順・CI・出荷候補IPAでの実機確認。OS/署名由来の制約と基盤の未対応を区別 |
| V5 | 作者へ都度相談せず追加・更新・運用できる | WindowsからActionsを使う手順、依存・権限・保存先の分離、基盤更新時の互換性方針、例とテストの対応 |
| V6 | 検証したsourceと配布物が一致する1.0を届ける | 出荷候補の全CI、対象commit、版番号、変更履歴、実機結果、最終公開手順とrelease asset |

自動変換器、動的IPA実行、ストア、クラウド同期、全機種保証は追加しない。Featureの機能・画面数・保存方式を固定しない。検証用アプリが動くことと製品の完成は区別する。

## 現在の到達点と残作業

個別D項目の状態・source・検証証拠は[統合差分台帳](../../coexistence-ledger.md)を正本とする。
完了済みの初期実装を未着手として再計画せず、部分補完と領域全体の完了を区別する。

| 作業のまとまり | 到達点 | 再開後に残る範囲 |
| --- | --- | --- |
| 独立開発・組込み（V1/V2/V5） | Tuist雛形、単独Feature、統合host、Recordsの実用データ/画面と共存を検証 | 幅広いFeatureに対する未補完境界、一般extension/依存の接続・診断 |
| 保存・復元（V3） | JSON/添付ZIP、選択復元、stop/apply/resume、停止失敗回復、通常保存操作との調停、SQLite比較 | 他DB、別process、移行/リセット、任意の処理・接続の寿命登録 |
| 活動・画面・処理寿命（V0/V4） | host/sceneイベント、Feature別経路、Task取消/完了待ち、購読、idle lease | 実OS複数window、提示、一般外観、非協調処理や障害の緩和 |
| OS・外部サービス接続（V0/V4） | 通知/URL/検索、Keychain/Web/通信、background登録と再接続、共有refresh、Package Widget/Intentsの部分検証 | 台帳にある実OS受付/起動・同意/資源調停・任意SDK・外部identity等 |
| 配布（V6） | 0.6.0を検証sourceから公開し、公開IPA再取得も検証 | V0〜V5の不足を解消した1.0候補で回帰・必要な実機確認・最終公開判断 |

0.6.0後のSDK iOS比較とrefresh診断fixtureはmainにあるが未リリース。
1.0候補の新しい全検証や実機確認はまだ完了していない。
過去に「1.0候補」と呼んだ試験とV1〜V6のチェックは当時の範囲の実績であり、現在のV0達成ではない。

## 再開時の進め方

1. ユーザーの新方針を適用し、台帳から不足している補完単位を選ぶ。基礎実装済みの仕事を再実装しない。
2. 既存契約・比較baseline・検証範囲を揃え、[並列運用](../../parallel-implementation.md)に従いCI前にレビューする。
3. 実装と必要な検証をまとめて進め、成功sourceと残存制約を台帳へ反映する。0.x公開は適切な区切りで判断する。
4. 完成基準を満たした1.0候補に対して、[公開手順](../../releasing.md)の回帰・実機確認・公開判断を行う。

既存Counter/Reminderの識別子・保存値・通知とバックアップ読込み互換性を維持する。
ignoredのZaiko source/testsは保持し、通常製品へ戻さない。既報のupstream issueを重複作成しない。

旧チェックリストと逐次計画は[履歴資料](../../history/1.0-plan-before-0.6-doc-sync.md)へ保存した。
