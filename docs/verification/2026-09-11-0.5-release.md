# JibunKit 0.5.0公開検証

## 出荷範囲

本体/Widgetの表示versionを0.5.0、buildを6とする。通常IPAはCounterとReminder。
Zaikoのローカル除外を維持し、native比較用のFeatureや独立fixtureを製品Registryへ追加しない。
bundle ID、App Group、保存キー、Counterの公開Intent識別子は維持する。

0.4.0以後の主な成果は、FeatureをNavigationStackのrootへ置く遷移修正、Keychainの
SecAccessControl/LAContext対応、Web認証の所有者別取消、URL resolver/宣言の接続、
Feature起動hook、BackgroundTasks/Background URLSessionの所有権と再接続基盤、
Swift PackageのApp Intents・Feature所有Shortcut合成と識別子/参照の統合検査。

同名Intent/entity/queryを一律に禁止せず、標準persistentIdentifierで分離できることを確認した。
各Featureが所有権・保存・寿命の接続を行う前提は維持する。v1.0の共存基準は未達。

## 証拠と残件

Keychain access-controlはユーザー実機で非対話の保護読取/更新拒否、認証後の元の値、
他owner保持を確認済み。通常CounterのShortcut合成は合成前の公開metadataとの互換性を検査する。
直前の通常UI全件は34553604092、最新のPackage Intent/同名型比較とgenerated hostは34561579846。
出荷候補では通常UI全件とFiles経由の選択復元を再実行する。

BackgroundTasksのpending要求照合はSimulatorが標準nativeでも拒否するため実機に残る。
アプリ全体の1 refresh/10 processing枠のFeature間調停は未実装。Background URLSessionの
起動中の実転送・保存・取消は確認したが、OSによるcold launch再接続は未実証。
Now Playingは音源なしのsession別状態までで、実再生/Control Center配送は別作業中。
OS Shortcuts/Siriからの選択・実行、一般Widget組込み、その他の共有資源は台帳に残す。

この出荷候補ではgenerated Feature全体のUIや全native比較を再実行せず、上記の個別CIを根拠とする。
通常IPAそのものの新たな実機確認はまだ行っていない。

## 公開状態

候補を準備中。出荷CI、source、artifact、直接配布URL、SHA-256は成功後に記録する。

## 最初の出荷CIで見つかったZIP名の問題

[34563217118](https://github.com/y-aplus/JibunKit/actions/runs/34563217118)、source
`93162fe92530a014660ca8e664158b47152469aa` はZIP round trip試験の保存名編集で失敗した。
入力対象`DOCPicker.filenameTextField`がkeyboard focusを持たず、XCTestのtypeTextが失敗した。
ログには保存候補`backup`が残り、ZIPの転送元URLが`backup.zip`、TransferableのsuggestedFileNameも
固定だった。画面のdefaultFilenameだけではZIPの候補へ日付名が渡っていなかった。

ZIPを最初から画面が決めた日付名で生成し、FileRepresentationのsuggestedFileNameも実際の
ファイル名へ揃える。ストリーム生成とworkspace所有は維持し、全体をDataへ読んだり複製しない。
名前引数は単一path componentへ限定してexport前に拒否する。ZIP UI試験は手動改名を行わず、
日付名が提示されることを要求し、その名前のファイルを保存・再選択して復元する。
この変更の成功は次のCIで確認する。

## ZIP修正の確認とJSON試験のファイル選択修正

[34565368233](https://github.com/y-aplus/JibunKit/actions/runs/34565368233)、source
`cb24ed43eb88aa47d37d87953caea552212500f8` で共有187試験（既知のKeychain 2 skip、失敗0）、
通常UI 11試験（474.017秒）が成功。ZIPの日付名・添付復元は78.906秒で成功した。
通常app/WidgetとIPA検査も成功したが、後続のFiles JSON復元試験で失敗した。

Filesの一覧には先行試験の`JibunKit-backup-20260911-052804.zip`と今回書き出した
`JibunKit-backup-20260911-053407.json`が共存していた。試験が共通prefixのfirstMatchで
ZIPを選び、Counterを含まない添付fixtureの復元画面でCounterの選択肢を待って失敗している。
一覧画像とtapログの選択先が一致し、JSON保存の失敗や読込機能の回帰を示すものではない。

JSON試験は保存画面の提示名を取得し、拡張子を含めた今回のファイル名を指定する。
先行ZIPを消して問題を隠さず、通常UIからFiles試験までの同じ順序で再検証する。

次の[34566799963](https://github.com/y-aplus/JibunKit/actions/runs/34566799963)、source
`03db3d7615b6c9a722a14bd8fbb945f4a8069d1e`では、JSON保存画面に
`DOCPicker.filenameTextField`が現れず、保存操作前に追加した名前取得assertionで失敗した。
失敗時のUI hierarchyには保存ボタンと既存ZIPはあるが、TextField要素自体が存在しない。
ZIP用Transferableのexporterで観測した内部IDを、JSON用FileDocumentのexporterにも
要求していたことが問題で、今回のJSON選択にはまだ到達していない。

この試験は新規CI Simulator上で一度だけJSONを書き出す。保存名欄の構造に依存せず、
保存後のFiles一覧で日付名かつ`.json`の候補を一件だけ要求し、その完全な名前を二度の
importに用いる。既存ZIPを保持し、候補が複数なら任意の一件を選ばず失敗させる。

34566799963の共有187試験は既知の2 skip/失敗0、通常UI 11試験は543.442秒で成功。
ZIP round tripも95.442秒で成功しており、今回の変更はJSON UI試験と記録だけに限定する。
