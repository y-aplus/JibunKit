# 並列運用の再点検

2026-09-11、BackgroundTasks、Background URLSession再接続、host起動hookをmainへ統合した時点で点検した。独立作業は進んでいるが、Sol lowへ寿命・完了条件の設計まで広く任せた単位では、親のレビュー往復が多かった。**節約率は不明。並列数とモデルを増やさず、次の分担を調整する。**

親はこの間、App Shortcutsのnative抽出比較と通常host接続も実装した。完全な管理専任にはなっていないが、ワーカー成果の再レビュー・共有CIへの接続が親へ集中している。上表だけで直列より速い、Pro枠を節約できたとは結論しない。モデル別利用量、管理だけのtoken、同難度の直列比較値は取得できていない。API価格からPro枠を換算しない。

## 次の運用

- Astra lowは共通APIの所有権・寿命・取消と完了の契約、および共有host接続を担当する。大きな契約を複数ワーカーへ別々に設計させない。
- Sol lowは独立したnative比較、実HTTP fixture、境界が決まった実装と回帰を並行して持つ。現在のNow Playing比較とbackground download比較が該当する。標準APIで足りる場合は独自機構を増やさない。
- 新しいcallback所有権の単位では、初稿前に「登録解除と実行終了」「期限後の保持」「重複・遅延・再入」「OS completionを呼べる時点」を具体的な操作列で決める。全ての小変更への汎用チェックリストにはしない。
- 同じ単位で契約修正が反復したら、さらに小さな修正指示とCIを往復するより、その契約設計を親へ戻す。ワーカーはその間、独立した検証を担当する。
- 現在の完了通知による再開を維持し、短い間隔の監視や、枠を埋めるだけの新規実装を増やさない。追加のモデル昇格は行わない。

実装と検証がmainへ入るまでを成果とする基準は変更しない。今回の再配置でレビュー往復が減るかを、次の意味のある統合時点で判断する。
