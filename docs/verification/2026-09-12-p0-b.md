# P0-B 画面・同意・無効化/削除

2026-09-12。実装中、Swift/iOS未検証。P0-A候補cd45ea8から分岐し、そのCI完了通知を待つ間に独立部分を進める。

## 現在の実装

- Feature別同意宣言/保存とCounter/Reminder削除providerを別担当から取り込んだ。データ形式/キーを変更せず所有キーだけ削除する。
- 共通管理層は最初のawait前に起動受付を閉じ、無効化/削除の意図をowner別に永続化。保存領域の排他予約、Runtime終了、所有登録解除、削除、同意消去の順で処理する。
- 無効化はデータ/同意を保持する。削除は再登録まで起動を拒否し、再登録で以前の同意を復活させない。解除/削除は再試行可能であることをcallback契約とする。
- エラーでは途中状態と失敗段階を残す。再起動でも途中状態を有効に戻さない。終了が進まなければ待機処理/解放件数を管理画面で表示する。
- 通常hostの一覧、経路解決、通知、scene/hostイベントに受付条件を接続。cold launchのネイティブ登録自体は必要時刻に行い、そこからの業務処理はFeature lifetime経由の契約を維持する。
- アプリ内管理画面に無効化、再有効化、対象/データ説明と確認付き削除、再試行、利用同意変更を追加。リマインダーの通知操作に目的/拒否時動作の説明と同意判定を接続。
- Counter更新、Reminder保存/通知の通常ボタン処理をRuntime所有にして、削除前の終了待ちへ含める。

## 検証と残件

Core tests追加: Aの無効化でデータ保持、削除と再登録で同意初期化/B保持、削除失敗後の再起動と再試行、保存予約競合時の保持。
