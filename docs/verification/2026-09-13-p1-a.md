## 親の現在実装

MiniAppIncomingStore: App Group内のowner別receipt。NSFileCoordinatorの短いcatalog同期とowner別コピー/削除同期を使い、部分コピーは公開しない。admission世代の再確認で、disable→enableを跨いだ古い入力の公開を拒否する。disabledのpending保持とdeletedのowner限定削除、破損receiptの独立報告、安定receipt IDで再試行可能にする。受け手の業務DBとinbox ACKは別commitなので、receive側はreceipt IDによる冪等化を実装する。

MiniAppIncomingFileAccess: security scopeを取得できた場合だけstopし、NSFileCoordinator読み取り内でコピーする。NSItemProvider callback内でコピーを終え、一時URLをcallback外へ渡さない。ProviderLoaderはProgress取消/続行の一回完了を扱い、取消時にcallback未到着でも待機を解き、コピー中ならcallbackをdrainしてから一時フォルダを消す。

MiniAppIncomingProvider/Delivery: optional Definition adapter。通常owner lifetime/Runtimeとstore-access予約の中でreceiveを待ち、正常commit後にACK。失敗はreceiptを保持。二sceneの同じreceiptの重複実行をprocess内で拒否。Feature自体はこのadapterを使わなければ追加機構は不要。

Registryはincoming ownerの登録解除時にshared catalogを閉じ、無効化ではpending保持、データ削除でpendingも削除、再有効化で登録し直す。通常Core/host変更なのでP0の関連管理/復元/寿命回帰を再実行する。

本体の外部file URL/受信一覧/対象選択/取込み・取消・失敗・再試行UIとShare Extension targetを追加。既存backup/管理sheetを外部入力で強制終了しない。共有保存成功と取消の二重OS完了を防ぐ。別sceneの実行中receipt破棄もDeliveryで拒否する。

二つの通常Definition + 独立JSON文書storeのP1IncomingProbe/P1IncomingUITestsを追加。保存後の応答失敗→再起動→同じreceiptを再試行しても二重保存しない経路、B保持を実際の本体UIで試す。ShareLinkによる文字列/URL/ファイルのOS操作は0.8候補で確認する。

追加した検証: IncomingNativeTestsでiOS NSItemProvider実体・callback取消・FileAccess・Store・Delivery、macOS executableで別processの200受信、Aのpin中のB保存、A削除待ち/閉鎖/B保持。通常IPAと診断IPAは埋込みShareのInfo/arm64/版/App Group/署名を検査してからhostを署名する。[開発者ガイド](../guides/feature-incoming.md)。

## 標準契約を確認した資料

- [Apple: extensionと本体の共有コンテナー/同期](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionScenarios.html)。NSFileCoordinatorを含む標準同期を使う。
- [Apple: loadFileRepresentation](https://developer.apple.com/documentation/foundation/nsitemprovider/loadfilerepresentation(fortypeidentifier:completionhandler:))。一時コピーはcallbackの終了で削除される。
- [Apple: security scope](https://developer.apple.com/documentation/foundation/url/startaccessingsecurityscopedresource())。取得/解放を対応させる。
- [Apple: loadItem](https://developer.apple.com/documentation/foundation/nsitemprovider/loaditem(fortypeidentifier:options:completionhandler:)) はProgressを返さない旧APIのため、URL/文字列にloadObjectを使用する。
