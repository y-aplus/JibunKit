# Issue #6の1.0境界採用

2026-09-15、0.8.0の公開・公開再取得検査後にユーザーへ確認し、「Issue #6の推奨境界を採用する（推奨）」との回答を受領した。

P0/P1維持、P2-A全6領域とP2-B全4領域の通常範囲を必須とする。P2-Cは既存成果で比較的低負荷に成立する範囲を採用し、P3特殊構成・万能互換性/高度隔離は後段へ残す。通常の中断・復帰・背景動作・所有者分離は省略しない。署名/外部資源条件、補完不能、未実装を区別する。

[優先実装](../implementation-priorities.md)と[補完責任](../coexistence-boundaries.md)へ正式範囲を反映した。機械可読計画と検査ツールの拡張は同じ変更境界で扱う。採用したP2-Cをinspectionだけで完成扱いできないよう、採否評価と採用後の実装/検証を分ける。

0.8.0の出荷時点の確認commit・全件一覧と公開assetは[出荷記録](2026-09-15-0.8-release.md)に固定されている。公開後に新しい計画を追加した現在treeと、出荷時の文書snapshotを混同しない。過去tag/evidenceを新計画への追随のために書き換えない。

P2-7の事前確認では、MiniAppStorage.withExclusiveAccessとMiniAppRestoreCoordinatorはprocess内だけの調停、MiniAppManagement.savedStatusは時点読込みであり、別processの予約ではないことをソースで確認した。静的Widgetの成功を操作Widget/Controlの安全な書込みへ読み替えず、app/extension間の保存・管理競合を最初のまとまりに含める。

## 計画と検査の結果

plan.json/schema2にP2の13追跡単位を追加した（10必須機能、3採否/採用範囲）。旧IDの意味、P0/P1と0.7/0.8 milestoneを維持し、1.0 milestoneは全必須条件と条件付きの採否/採用範囲を含む。7つの事前CI境界を追加。`python -X utf8 -m unittest discover -s Tools/tests -p test_delivery.py`は19件成功。P0/P1・必須P2/OS条件の省略、P2未完、未実証の採用範囲、理由や証拠なしの除外、未決定の完了、P2入力/時間見積り不足を拒否する。旧schema1の受入も確認した。

別レーンは保存済みJibunKit projectを指定したworktreeとして作成要求したが、内部のthread/worktree生成後にgh読み取りの承認待ちとなり、ユーザーのスレッド一覧にも表示されなかった。権限変更は行わず、ローカル本文を渡しても待機が解消しないため停止指示を送り親が担当を回収した。この試行を分担成功・節約実績と数えない。作成/追補/停止の指示と調査の管理負荷が増え、コード成果はなく、待機中のモデル定期pollは行わない。以後この作成経路で追加レーンを増やさない。
