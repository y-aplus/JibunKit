## 検証の再利用と追加範囲

実機確認済みsourceからの製品差分は3bundleの版/build番号だけ。実行コード・保存形式・ID・App Group・署名条件は変更しない。native/管理UI/実機を再実行する予定はない。通常35046699862、Alarm35046697413、Live/host35047576529の証拠を元sourceのまま参照する。

今回の追加境界は1run・独立2job。build-ios.ymlをcontinuing_state_validation=true、simulator_tests=false、feature_validation=false、records_validation=false、simulator_runtime空（他は既定）で実行する。

- 通常job: 0.8.2/build12のRelease/署名/metadata/IPA。従来workflow内の短い共有・Records・要求合成検査はそのまま使い、Simulator全回帰と独立Featureの再buildは行わない。直近同範囲35046699862は3分53秒、準備/upload込み10分見込み。
- continuing-state job: 実4Featureのstore/provider、公開管理・復元APIを接続する新規native XCTest1件だけ。4ownerへ非初期値を保存し、Live A/Alarm Aの無効化/再有効化、誤JSON拒否、選択JSON復元、削除/再登録、再prepareについて他3ownerの全業務payloadと世代の不変を検査。OS活動は開始せず、OS表示/鳴動の検査とはしない。Registry固有のSpotlight/通知cleanupは既存UIで検証済みのため重複実行しない。

state jobは通常診断hostのSimulator Debug buildと1件実行のみで、Release/独立A/B/Combined/metadata比較/既存UI/診断IPA作成を繰り返さない。既存host16分26秒からRelease buildとUI操作を除外し、新しいnative test targetのcompile/runを追加するため、準備/upload込み15分を見込む（新経路の実績ではない）。通常jobとは並列・依存なし、run最長見込み15分、30分目標。P2-L累計8run（7runは既存実績）。追加理由は実機後の版更新と、承認済みの手動検証削減を支える実Feature接続試験の補強で、実装の細分化による別々の投入はしない。

新試験が成功しても単発のB=200の原因解決とはしない。追加実機は依頼せず、保存値追跡の自動回帰結果として記録する。実機前に候補採番して再buildをなくす案はまだ提案であり、この承認で採番手順まで変えない。
