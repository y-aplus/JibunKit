# P2-L AlarmKit submission

- Baseline: `bcfde0d88c19a143620b16e71230e4fb404ae7f1`
- Deliverable: `docs/delivery/P2-alarm-design.md`
- Recommended boundary: Feature owns typed `AlarmConfiguration<Metadata>` creation and alarm meaning; infrastructure owns `(owner, localID, generation, Alarm.ID)` journal, admission, reconciliation, and management/restore sequencing; OS owns authorization and daemon state. Do not introduce an arbitrary timer/payload model.
- Native API: iOS 26 `AlarmManager.shared`; async throwing schedule/authorization; throwing stop/cancel/countdown/pause/resume; throwing `alarms` snapshot; nonthrowing alarm/authorization update sequences. There is no documented configuration update API, so the proposal exposes explicit journaled replacement rather than claiming update-by-reschedule.
- Apple primary sources: [AlarmKit](https://developer.apple.com/documentation/alarmkit), [AlarmManager](https://developer.apple.com/documentation/alarmkit/alarmmanager), [Apple sample](https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit), [WWDC25 session 230](https://developer.apple.com/videos/play/wwdc2025/230/), [`NSAlarmKitUsageDescription`](https://developer.apple.com/documentation/bundleresources/information-property-list/nsalarmkitusagedescription), [`LiveActivityIntent`](https://developer.apple.com/documentation/appintents/liveactivityintent).
- P2-W reuse: owner/generation/tombstone SharedState, management admission, owner reservation, restore lifecycle, and namespaced Intent fixtures. Not reusable as-is: OS registration journal, async OS/save recovery, AlarmKit-specific `LiveActivityIntent`, and explicit re-registration policy.
- Test/CI proposal: after parent contract integration, compile standalone A/B/combined/normal host with Xcode 26 and strict concurrency; verify built plist, signed entitlements/profile and Intent metadata; deterministic journal/failure/B-retention tests; then same-signing standalone-vs-host device experiment and one A/B management/restore/cold-launch sequence.
- Not verified here: Swift/Xcode execution, final SDK actor annotations, same-ID reschedule behavior, stop-vs-cancel state semantics, OS limits/error taxonomy, device reboot/first-unlock UI, and account/profile/ad-hoc/SideStore availability. No paid-account requirement is asserted.
- CI/push/product/shared-source changes: none. Parent runs CI after integration.
